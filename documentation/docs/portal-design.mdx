# The design of a portal

What a [developer portal](./developer-portal.mdx) looks like and says is its **design**. A portal
has one of three modes:

| Mode | What it is |
|---|---|
| **Default template** | the template of the product, as it is: the title and tagline of the portal, its accent color and logo, a home in Markdown, its pages |
| **Themed** | the same pages, themed: colors for the light and the dark themes, a font, a radius, a favicon, links in the header and the footer, a style sheet — and a home made of blocks |
| **Templates** | the home, the overview of an API and the free pages written as **templates** (Markdoc), the components of the portal as tags, on top of the theme |

In every mode, the pages where a consumer acts — subscribing, the applications and their
credentials, the usage, signing in — stay the product's, themed.

The design is edited in the console, **Developer portal** in the sidebar (only the administrators
of the workspace edit it; its producers read it), from a folder with the [CLI](./gitops/cli.mdx), or
from a [remote catalog](./gitops/remote-catalogs.mdx). Nothing of it reaches the gateway.

## A draft, published by versions

The design is a **draft**; **Publish** freezes it into an immutable **version**, and the portal shows
the last version published — before any, it shows what its settings describe, so a portal that has
never been designed is the default template, unchanged. **Preview the draft** opens the portal on the
draft, for an hour, with a banner — and with the errors of its templates, which the published portal
never shows. A version **restored** into the draft and published again is the rollback.

## The theme

| | |
|---|---|
| Accent | the color of the buttons and links, in every mode |
| Logo | an url, or an asset of the design |
| Favicon, font, radius | themed and templates only |
| Colors | background, surface, text, muted, border — for the light theme and for the dark one |
| Navigation | links in the header and the footer: the web (`https://…`), a mail (`mailto:…`), a path of the portal (`/apis`), an anchor, or a page of the design (`page:guide`) — never `javascript:` |
| Style sheet | css, themed and templates only |

The **home** of a themed portal is a list of **blocks**: a hero (the title and the tagline, a search),
the featured APIs, the cards of the catalogue (of a category, of a tag, a limit of them), its
categories, a Markdown section. In Markdown, an image or a link names an asset (`assets/logo.png`)
or a page (`page:guide`).

## Templates

In the mode **Templates**, the home (`home`) and the overview of an API (`api`) are templates, and
so are the free pages. A template is [Markdoc](https://markdoc.dev): Markdown, with tags and
variables — and nothing else runs: no html, no script. Its tags:

| Tag | |
|---|---|
| `{% catalogue category="retail" tag="…" limit=6 /%}` | the cards of the APIs of the catalogue |
| `{% featured limit=3 /%}` | the featured APIs |
| `{% categories /%}` | the categories, each a link to its APIs |
| `{% api-card api="books" /%}` | the card of one API |
| `{% api-reference api="books" /%}` | its reference, its OpenAPI rendered and tried from the page |
| `{% plans api="books" /%}` | its plans, and how to subscribe |
| `{% subscribe api="books" plan="plan_free" label="Get a key" /%}` | a button that subscribes |
| `{% button href="page:guide" kind="primary" %}…{% /button %}` | a link drawn as a button |
| `{% callout type="info" title="…" %}…{% /callout %}` | a highlighted note: info, warning, success, danger |
| `{% columns %}{% column %}…{% /column %}{% /columns %}` | columns side by side |

Its variables: `{% $portal.title %}`, `{% $portal.tagline %}`, `{% $lang %}`, `{% $user.signedIn %}`,
`{% $user.name %}`, and in the template of an API `{% $api.name %}`, `{% $api.version %}`,
`{% $api.description %}`, `{% $api.slug %}`, `{% $api.baseUrl %}`. Every text — a template, a page,
a block — is written per language of the portal.

## Assets

Images (png, jpg, gif, webp, avif, ico, svg), fonts (woff2, woff, ttf, otf) and style sheets, 2 MB
each, 20 MB for a portal, kept by their digest and served by the portal, never as anything else: an
svg is a document of its own, sandboxed. A script is never an asset.

## Scripts

A design can hold a script, and **it runs only if the administrators of the workspace allow scripts
on the portal** — off by default. Allowing them shows what it means, and asks to acknowledge it:

:::danger
A script of the design runs in the portal, in the session of every consumer who opens it: it can
read what they see — their applications, their credentials — and act on their behalf. Allow it only
for a script you wrote or reviewed, served by this portal alone.
:::

Allowing and forbidding scripts are in the audit trail. The page of the portal carries a **content
security policy**: its own scripts, its inline ones by a nonce, images and fonts of the web, no frame
of another site; a portal that allows scripts lets its script load others from the web (an analytics
tool, a chat).

## A folder, a catalog

The design is also a **folder**, that the CLI and the catalogs share:

```text
portal/
  portal.yaml                 # kind: Portal — the mode, the texts, the theme, the navigation, the blocks
  home.en.md                  # the home of the default template, per language
  pages/guide.en.md           # a page, per language
  templates/home.en.md        # the templates
  templates/api.en.md
  styles.css
  script.js
  assets/logo.png
```

`portal.yaml` names the files it uses (`content: { en: { file: pages/guide.en.md } }`,
`css: { file: styles.css }`, `assets: [{ path: assets/logo.png, file: assets/logo.png }]`), relative to
it and within the folder.

```bash
bun cli/apim.js portal pull default portal              # the draft into ./portal
bun cli/apim.js portal push default portal --watch      # every change into the draft, the preview link printed
bun cli/apim.js portal push default portal --publish    # the draft, then a version
```

A [remote catalog](./gitops/remote-catalogs.mdx) (git, S3, HTTP) that holds the same folder applies
the design and publishes it (unless it writes drafts only), and then owns it: the console shows it
read only, edited at its source.
